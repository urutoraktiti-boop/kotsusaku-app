# リマインダー通知 仕様書（Phase 1で実装）

2026-07-06 ユーザー決定。採用案とルールを記録する。
実装はアプリ版（Capacitor）のみ。Web版には通知機能を出さない。

## 採用した通知（3種類）

### ① スピリットの呼び声（毎日の顔・メイン）
- 育成中のスピリットが差出人になる。文面はスピリットの状態で変わる
- 例：「レイが待ってるよ」「覚醒まであと3コツ。今日の1コツで近づくよ✨」
- タップするとスピリット画面を開く
- データ源：スピリット編のデータ（`docs/kotsu-spirit-feature.md` 参照。能力表・覚醒Lv・残りコツ数）

### ② 開花日だより（毎朝の実用枠）
- 試験日（開花日）までの残り日数＋応援の一言
- 例：「🌸 開花まであと45日」「今日の10分が、花びら1枚になる。」
- 節目（100日・50日・30日・7日前）は特別文面。節目の日は①より②を優先
- データ源：`exam-date`（開花日カウントダウン `bloom-countdown.js` と同じ出どころ）

### ④ おかえり通知（責めない・戻る橋）
- 3日以上アプリを開いていない人にだけ届く。**週1回まで**
- 例：「おかえりの準備はできてるよ」「積み上げた87時間は消えてない。続きから、どうぞ🌸」
- 連続記録を責めない。累計が残っていることを伝える（コツサクの累計主義の通知版）
- データ源：累計学習時間（`getTotalStudyMin` 系）

### 見送り
- ③今日の一言（名言・ピヨ）は今回は採用しない（将来のアップデート候補として残す）

## 設計ルール（うるさくしない約束）

1. **デフォルトOFF**。設定画面の「⏰ リマインダー」でONにする（初回に1度だけやさしく案内してよい）
2. **1日1回まで**。通知時刻はユーザーが選ぶ（例：朝7時／夜20時などの時刻ピッカー）
3. ④おかえり通知だけは別枠（不在時のみ・週1上限）
4. **ローカル通知**（端末自身が鳴らす。サーバーに新たなデータを送らない）
5. ①と②は日替わりローテーション（偶数日=①、奇数日=② など単純な規則でよい。節目日は②優先）

## 実装メモ（Capacitor）

- プラグイン：`@capacitor/local-notifications`
- **予約制で組む**：ローカル通知は事前予約が必要。アプリ起動のたびに
  1. 既存の予約を全キャンセル
  2. その時点の最新データ（スピリット残りコツ・開花日残り日数・累計時間）で文面を生成
  3. 翌日から7日分を予約（ユーザー設定時刻）
  4. ④用に「今から3日後」に1本予約（次回起動でキャンセル→再予約。前回④送信から7日以内なら予約しない）
- 権限：初回ON時にOSの通知許可ダイアログを出す（拒否されたら設定画面に案内を表示）
- Web版分岐：`window.Capacitor` の有無で「⏰ リマインダー」セクションごと非表示
- 文面は将来調整しやすいよう、1か所の定数リストにまとめる（出どころを1つに＝失敗記録#005の教訓）

## プライバシーポリシーへの影響

- ローカル通知は端末内で完結するため送信データは増えない
- ポリシーに「リマインダー通知は端末内で動作し、外部にデータを送信しません」の1文を追加する（Phase 1実装時）
