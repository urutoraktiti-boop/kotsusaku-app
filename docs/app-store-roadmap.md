# コツコツサクサク アプリストア提出ロードマップ

App Store（iPhone）と Google Play（Android）に「本物のアプリ」として提出し、
審査に合格するまでの道のりをまとめた文書。

- 作成日：2026-07-06
- 対象読者：非エンジニアの運営者本人
- 前提：Macを所有／両ストア同時進行で進める

---

## 1. 全体像：いまのアプリと「ストアアプリ」の違い

### いまの姿

コツサクは **PWA**（プログレッシブ・ウェブ・アプリ＝ブラウザで動き、ホーム画面に
追加すればアプリのように使えるWebアプリ）として、Firebase Hosting
（Googleのホームページ置き場サービス）で公開されている。

### 目指す姿

App Store / Google Play からダウンロードできる「ネイティブアプリ
（携帯に直接インストールされる本物のアプリ）」にする。

### どうやって変身させるか：Capacitor（キャパシター）を使う

**Capacitor** は「いまのWebアプリを、そのまま中身として包み込んで、
iPhoneアプリ・Androidアプリの形に仕上げる道具」。無料で使える。

たとえるなら、いまのコツサク（index.html など）が「お弁当の中身」で、
Capacitor が「iPhone用・Android用それぞれのお弁当箱」を用意してくれる。
中身は作り直さなくていいのが最大の利点。

- コツサクは1つの `index.html` を中心にしたシンプルな構成なので、Capacitor と相性が良い
- Macを持っているので、iPhoneアプリも標準ルート（**Xcode**＝Apple公式の開発ソフト、無料）で作れる
- Androidアプリは **Android Studio**（Google公式の開発ソフト、無料。Mac版あり）で作る

### 大事な考え方の切り替え

いまのコツサクは「サーバー上のファイルを直せば全員に即反映」だが、
ストアアプリは「**ファイルをアプリの中に同梱し、更新はストア経由で配信**」になる。
つまり v114、v115…と更新するたびに、ストアに新しい版を提出する流れに変わる
（Webテスト版はいままで通り Firebase Hosting で並行運用できる）。

## 2. 審査に通らないポイントと対策（優先度順）

### 🔴 最重要①：プライバシーポリシー（個人情報の扱い方の説明文）が無い

**現状**：アプリ内・リポジトリ内のどこにもプライバシーポリシー・利用規約・
連絡先が存在しない（全文検索で確認済み）。

**なぜ致命的か**：Apple も Google も「プライバシーポリシーのURL」の提出を
**必須**にしている。無ければ提出画面すら先に進めない。

**コツサクが説明すべき内容**（実態に合わせて正直に書く）：

| アプリがしていること | 説明すべきこと |
|---|---|
| 匿名の利用データ（学習時間・端末の種類・レベルなど）をFirestore（Googleのデータ保管サービス）に送信 | 何を・何のために送るか（アプリ改善・「みんなの軌跡」の集計のため）。名前やメールは集めていないこと |
| Google Analytics（Googleのアクセス解析）でアプリの利用状況を記録 | 解析ツールを使っていること |
| 同期コードを使ったクラウド保存（`users/{同期コード}`） | 学習記録がクラウドに保存されること、削除方法 |
| メモ・応援メッセージなどはローカル（端末内）保存が基本 | 端末の外に出ないデータの範囲 |

**対策**：
1. プライバシーポリシーのページを作る（既存のホームページ
   `urutoraktiti-boop.github.io/kotsusaku-homepage` に置くのが手軽）
2. アプリ内の設定画面からリンクを張る
3. ストア提出時にそのURLを登録する
4. あわせて「お問い合わせ先（メールアドレス等）」も明記する（両ストアで必要）

### 🔴 最重要②：Appleの「ガイドライン4.2（最低限の機能）」リスク

**なにそれ**：Appleには「Webサイトをただアプリの形に包んだだけのものは
App Storeに置かない」というルール（審査ガイドライン4.2）があり、
PWAをそのまま包んだアプリはこれで落とされることが多い。

**コツサクの強み（すでに有利な点）**：
- オフライン（電波が無い状態）でも全機能が動く＝「ただのWebサイト」ではない
- ストップウォッチ・レベル・スピリット・バッジなどアプリらしい体験が豊富
- 広告なし・課金なし・ログイン不要

**それでも足したい「アプリならでは」の機能**：
- **学習リマインダー通知**（ローカル通知＝携帯自身が決めた時刻に鳴らすお知らせ。
  例：「🌸 今日のコツコツの時間だよ！」）。現在のコツサクには通知機能が一切なく、
  習慣化アプリとの相性も抜群なので、審査対策と利用者メリットを両取りできる一番の候補
- （余力があれば）ホーム画面ウィジェット、触覚フィードバック（ボタンを押したとき手に伝わる振動）など

### 🟠 重要③：クラウドデータを利用者自身が削除できる手段が無い

**現状**：同期コードでFirestoreに保存した学習データを、利用者が消す方法がない。

**なぜ必要か**：Appleは「アプリがデータを預かるなら、利用者自身がアプリ内から
削除できること」を求める（ガイドライン5.1.1系）。プライバシーポリシーにも
削除方法を書く必要があるため、機能として用意しておくのが確実。

**対策**：設定画面に「クラウドの同期データを削除する」ボタンを追加
（Firestore上の `users/{同期コード}` の書類を消す。端末内のデータは残す）。

### 🟠 重要④：Firestoreのセキュリティルール（データ保管庫の鍵のルール）が未整備

**現状**：リポジトリ内にセキュリティルールのファイルが無い。同期データは
「同期コードを知っていれば誰でも読み書きできる」状態の可能性が高い。

**なぜ必要か**：審査で直接見られる項目ではないが、公開アプリとして利用者が
増える前に必ず整えるべき安全対策。悪意ある人が他人のデータを書き換えたり、
集計用データを壊したりできない仕組みにする。

**対策**：
- `users/{同期コード}`：書き込める内容の形式チェック（サイズ上限など）を入れる
- `analytics/{匿名ID}`：自分の書類以外は書けないよう制限
- `analytics_summary` / `analytics_task_trend`：クライアント（アプリ側）からの書き込みを全面禁止（読み取り専用）

### 🟡 中程度⑤：アプリ内自動更新の仕組みがネイティブ版と噛み合わない

**現状**：`sw.js` と `version.json` による「新しい版が出たら知らせて
入れ替える」Web前提の仕組みが入っている。

**問題**：ネイティブ版ではファイルをアプリに同梱するため、この仕組みは不要になる。
またAppleは「審査を通さずアプリの動きを後から大きく差し替えること」に厳しいので、
「Webから最新版を取ってくる」動きは残さない方が安全。

**対策**：ネイティブ版では更新チェック・更新ポップアップを動かさないように
条件分岐する（Capacitor上で動いているかは判定できる）。`notice.json` の
お知らせ機能は「表示するだけ」なので、そのまま残して問題ない。

### 🟡 中程度⑥：バージョン表記の不整合（小さいが直すべき）

**現状**：`sw.js` / `version.json` は `kotsusaku-v113-bloom-diary` なのに、
分析データとして送っている appVersion は `kotsusaku-v110-datafix` のまま
（index.html の1341行目・1686行目付近）。

**対策**：バージョン文字列の「唯一の出どころ」を1か所に決めて、全部そこから
参照するように統一する。ストア提出時は「1.0.0」のような世間標準の番号も
別途決める（内部のv113とは別に、ストア用の番号を持つ）。

### 🟢 心配しなくてよい点（コツサクの有利なところ）

- **課金・広告・購入が無い** → 審査で一番揉めるお金まわりの項目が丸ごと無関係
- **子供向けアプリではない**（大人の受験生向け） → 子供向け特有の厳しい規則が適用されない
- **カメラ・位置情報・マイクを使わない** → 権限（アクセス許可）まわりの審査項目がほぼ無い
- **ログイン機能が無い** → 「Appleでサインイン」対応義務も、アカウント削除機能の義務も発生しない
  （ただし③のクラウドデータ削除は必要）
- **日本語のみ** → 問題なし。ストアの公開地域を「日本のみ」に設定すればよい
- **暗号化は標準的なHTTPS通信のみ** → 輸出コンプライアンス（暗号技術の輸出規制の確認）は「免除に該当」と申告するだけでよい

## 3. 必要なアカウント・費用・素材

### アカウントと費用

| 項目 | 費用 | 備考 |
|---|---|---|
| Apple Developer Program（Appleの開発者登録） | **年間 約15,800円**（毎年かかる） | Apple IDで申し込み。個人登録なら本人確認のみでOK。登録完了まで数日かかることがある |
| Google Play Console（Googleの開発者登録） | **初回のみ 約25ドル（約4,000円）** | Googleアカウントで申し込み。本人確認書類が必要 |
| Capacitor / Xcode / Android Studio | 無料 | Macにインストールする |

### ⚠️ Google Play 個人アカウントの特別ルール（重要）

新規の個人開発者アカウントは、一般公開の前に
**「12人以上のテスターを集めて、14日間連続のクローズドテスト（限定公開テスト）」**
を実施することが義務付けられている。

→ **対処案**：C-teamコミュニティ（YouTubeの勉強ライブ仲間）に協力をお願いする。
テスターはGmailアドレスを登録してもらい、テスト版をインストールして
14日間使ってもらうだけでよい。コツサクにはうってつけの応援団がいる。

### アプリアイコン（作り直しが必要）

| 用途 | 必要なもの | 現状 |
|---|---|---|
| iOS提出用 | **1024×1024px・透過（透明部分）なし**のPNG | ❌ 無い（192/512pxのみ） |
| Androidアダプティブアイコン | 前景・背景を分けた素材（丸や四角に自動で切り抜かれる方式） | ❌ 無い |
| 既存 | icon-192.png / icon-512.png / icon.svg | ✅ あり（デザインの元にできる） |

### ストア掲載素材（両ストアで必要）

- **スクリーンショット**：実機やシミュレーター（Mac上で動くiPhoneの模擬画面）で撮影
  - iPhone用：6.9インチ・6.5インチなど指定サイズ（Xcodeのシミュレーターで撮れる）
  - Android用：携帯サイズ数枚
- **アプリ説明文**：アプリの紹介文（何ができるか、誰向けか）
- **アプリ名**：「コツコツ✏️サクサク🌸」※絵文字はストアの規約で使えない可能性が高いため、
  「コツコツサクサク」等の表記も用意しておく
- **サポートURL**：既存のホームページ（GitHub Pages）を流用できる
- **年齢レーティング**：質問票に答えるだけ（暴力表現・ギャンブル等すべて「なし」なので最低年齢区分になる見込み）

## 4. 工程表（フェーズ分け）

すべての工程は、このClaude Codeセッションで一緒に進められる
（Macでの操作が必要な部分は、貼り付けるだけのコマンドを毎回用意する）。

### Phase 0：リポジトリ内でできる準備（目安：数日）

審査必須項目を先に潰す。**Webアプリ側にもそのまま良い改善になる**。

- [x] プライバシーポリシーを作成（`privacy.html`。本番反映後は kotsusaku-app.web.app/privacy.html で公開）※お問い合わせ先は専用アドレス開設後に差し替え
- [x] アプリ内（設定画面）にプライバシーポリシーへのリンクを追加
- [x] 「クラウドの同期データを削除する」機能を追加（削除＋同期停止＋再開ボタン）
- [x] バージョン文字列の統一（`KOTSUSAKU_APP_VERSION` に一本化）
- [ ] お問い合わせ用メールアドレスを開設し、privacy.html に記載
- [ ] Firestoreセキュリティルールの整備とデプロイ（本番環境への反映）

### Phase 1：ネイティブアプリ化（目安：1〜2週間）

- [ ] Capacitorを導入（リポジトリに iOS / Android 用のフォルダが増える）
- [ ] ネイティブ版では更新ポップアップ・sw.js を動かさない条件分岐を追加
- [ ] 学習リマインダー通知（ローカル通知）を実装 ※仕様決定済み → `docs/reminder-notification-spec.md`（スピリットの呼び声・開花日だより・おかえり通知）
- [ ] MacにXcode・Android Studioをインストール
- [ ] シミュレーターと実機（自分のiPhone / Android）で動作確認

### Phase 2：ストア登録・素材準備（目安：1〜2週間　※審査待ち含む）

- [ ] Apple Developer Program に登録（承認まで数日待ち）
- [ ] Google Play Console に登録
- [ ] アイコン制作（1024px版・アダプティブ版）
- [ ] スクリーンショット撮影・説明文作成
- [ ] **TestFlight**（Appleの公式テスト配布の仕組み）で自分のiPhoneに配布して最終確認
- [ ] Google Play クローズドテスト開始（C-teamの12人以上に協力依頼、14日間）

### Phase 3：提出・審査対応（目安：数日〜2週間）

- [ ] App Store に提出（初回審査は通常1〜3日。リジェクト＝差し戻しは初回はよくあること。
      指摘内容を直して再提出すればよい）
- [ ] Google Play のクローズドテスト完了後、一般公開を申請
- [ ] 公開後：ストア経由の更新手順を確立（v114以降の出し方）

## 5. 提出前チェックリスト（最終確認用）

### 両ストア共通
- [ ] プライバシーポリシーURLが有効で、アプリ内からも開ける
- [ ] お問い合わせ先が明記されている
- [ ] クラウドデータの削除機能が動く
- [ ] オフラインで起動・全機能が動く
- [ ] 実機で新規インストール→初回起動→主要機能を一通り確認

### App Store（Apple）
- [ ] 1024×1024px 透過なしアイコン
- [ ] 指定サイズのスクリーンショット
- [ ] App Privacy（プライバシー質問票）の回答：「分析データを収集・ユーザーと紐付けない」等、実態どおりに申告
- [ ] 輸出コンプライアンス：標準HTTPS のみ＝免除に該当と申告
- [ ] 審査メモ欄に「同期コードの仕組み」を説明（審査員がログイン情報を探して戸惑わないように）

### Google Play
- [ ] データセーフティフォーム（データの安全性の申告書）の回答
- [ ] クローズドテスト 12人×14日間 完了
- [ ] 対象APIレベル（Androidの対応バージョン要件）を満たす（Capacitorの最新版を使えば自動的に満たせる）

## 6. 次の一歩

**Phase 0 の「プライバシーポリシー作成」から始めるのがおすすめ。**
理由：①両ストアで絶対に必要 ②他の作業と独立していて今すぐ着手できる
③ホームページに載せるだけなので失敗リスクが無い。

このセッション（または新しいセッション）で「プライバシーポリシーを作って」と
依頼すれば、コツサクの実態（匿名分析・同期コード・ローカル保存）に合わせた
文案作成から着手できる。
