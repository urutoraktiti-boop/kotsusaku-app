# 軌跡のしおり（新たな旅の始まり。）

「9月から科目を変える」「同じ科目だけど気持ちを新たに数え直したい」ときに、
**8月までの軌跡は残したまま、9月からの学習時間を0から数え直す**ための機能。

画面上の呼び名は **「軌跡のしおり」**。本にはさむしおりと同じで、
**ページは1枚も破らない**（記録は消えない）。挟んだところから読み直すだけ、というたとえ。
コードの中の名前だけは英語のまま（`seasonStart` / `seasonTotal` など）。
言い回しを変えたくなったときに、直す場所が画面の文言だけで済むようにしてある。

---

## 何ができるか

設定 →「基本設定」→「はじめに」→ **軌跡のしおり** に日付を入れるだけ。
**しおりは何枚でも挟める**（毎年でも）。いちばん新しい1枚が「いまの旅の始まり」になる。

| 場所 | しおりなし（初期状態） | しおりあり（例：9/1） |
|---|---|---|
| 📚 累計学習時間カード | 「累計学習時間」＝全期間の合計 | 「9/1〜の軌跡」＝9/1以降の合計。下に「🔖 しおりまでの軌跡（〜8/31） ○時間」を1行で表示 |
| カードの1日平均・学習日数 | 全期間 | 9/1以降 |
| 開花予測（試験日までの予測） | 累計 ＋ 1日平均×残り日数 | **9/1以降の実績だけ**で予測（前の期の時間は混ざらない） |
| レベル・バッジ・スピリット・ストーリー | 全期間 | **全期間のまま（変えない）** |
| 科目別カードの「累計」 | 「累計」＝全期間 | 「9/1〜」＝9/1以降だけ（日・週・月の3つとも） |
| 週タブ・月タブ・ヒートマップ | 変化なし | 変化なし |
| 設定の「これまでの旅」一覧 | 出ない | 第1の旅・第2の旅…と、しおりで区切った期間ごとの合計を表示 |

### しおりの操作（設定画面）

| 操作 | 何が起きるか |
|---|---|
| 日付欄に入力 | **いまのしおり**（いちばん新しい1枚）の日付を差し替える。1枚も無いときは1枚目を挟む |
| ✕ | **いまのしおりを外す**（1枚前の旅に戻る）。押すたびに1枚ずつ外れる |
| ＋ 新しいしおりを挟む | **今日の日付**で1枚足す。足したあと日付欄で直せる |

**決まりごと：しおりは前のしおりより後の日付でなければならない。**
違反すると「❌ 前のしおり（2026/9/1）より後の日付にしてください」と出て、変更は入らない。
いまのしおりが未来の日付のときは＋ボタンが使えない（今日の日付で足すため）。

### レベルとバッジを数え直さない理由

数え直しの対象にすると、9月1日にレベルが1に戻り、獲得済みバッジが消えたように見える。
積み上げてきたものが減る体験は避けたいので、**「数え直すのは時間の表示と予測だけ」**とした。

---

## 大事な前提：記録は1件も消えない

この機能が持っているのは**日付の一覧だけ**（`CUST.seasonMarks`）。
学習記録の本体（`study-data`）には一切触らない。

- しおりを外せば（✕ボタン）、**すぐ元の「全期間の累計」表示に戻る**
- クラウド同期・バックアップ・「みんなの軌跡」の全体合計にも影響しない
- 設定の「すべてリセット」とはまったく別物（あちらは本当に記録が消える）

## 関係するコード（`index.html`）

| 名前 | 役割 |
|---|---|
| `CUST.seasonMarks` | しおりを挟んだ日の一覧（`['2026-09-01','2027-09-01']`、空配列＝しおりなし）。`study-cust` に入るので**クラウド同期に自動で乗る**＝他の端末でも同じしおりになる |
| `getSeasonMarks()` | しおりの一覧を取り出す（古い順・重複なし・形式チェック済み） |
| `getSeasonStart()` | **いまのしおり**＝いちばん新しい1枚。累計カードも予測もこの関数しか見ていないので、しおりが何枚あっても集計の中身は変わらない。`CUST` の初期化前に呼ばれても落ちないよう try/catch（教訓#004） |
| `getJourneySegments()` | 「これまでの旅」の一覧。しおりで区切った各期間の合計（分）・学習日数を返す。最初のしおりより前にも記録があれば、それも第1の旅として先頭に入る |
| `_migrateSeasonMarks()` | 昔の形（`seasonStart`＝1枚だけ）で保存された設定を、いまの形（`seasonMarks`）に移す。`loadCust()` から毎回呼ぶ |
| `seasonTotal()` / `seasonDays()` | しおり以降の合計（分）と学習日数。しおりなしなら `allTimeTotal()` / `allTimeDays()` と同じ |
| `beforeSeasonTotal()` | しおりより前の合計（分）＝「しおりまでの軌跡」 |
| `subjectSeasonTotals()` | 科目ごとの合計（分）。しおり以降だけを数える。科目別カードの右側の数字。しおりなしなら全期間（旧 `subjectAllTimeTotals`） |
| `_fmtSeasonMD()` / `_fmtSeasonPrevLabel()` | `'2026-09-01'` → `'9/1'` / `'〜8/31'` |
| `renderAllTimeCard()` | 累計カードの描画。しおりがあれば見出し・数字・日数をしおり以降に切り替え、`.atc-prev` の行を足す |
| `renderForecast()` | 予測の集計に `seasonTotal()` / `seasonDays()` を使う |
| `_setSeasonStartValue()` | 日付欄の処理。いまのしおりを差し替える（空なら1枚外す）。前のしおりより前の日付は弾く |
| `_addSeasonMark()` | 「＋ 新しいしおりを挟む」。今日の日付で1枚足す |
| `_saveSeasonMarks()` / `_syncSeasonUI()` / `_renderJourneyList()` | 保存と、設定画面（入力欄・説明・＋ボタン・一覧）の描き直し |

### 集計キャッシュの注意

`_statMemo`（集計結果の使い回し）は**学習データが変わったときにしか消えない**。
しおりの日付を変えただけでは消えないので、`seasonTotal` / `seasonDays` は
**キーにその日付を含めている**（`'seasonTotal|2026-09-01'`）。
新しく期間別の集計を足すときも同じようにすること。

### 保存のタイミング

しおりは、他の設定（保存ボタンでまとめて確定）と違い、**操作したその場で保存**する
（`saveCust()` ＋ `persistTopSettingsNow()`）。試験日と同じ扱い。
設定画面を✕（キャンセル）で閉じても消えないよう、巻き戻し用の `_custSnapshot` にも書き込んでいる。

### 配列を共有しない

`CUST={...CUST_DEFAULTS}` は**中の配列を共有してしまう**（浅いコピー）。
`seasonMarks` に直接 push すると `CUST_DEFAULTS` まで汚れるので、
`_migrateSeasonMarks()` と `_saveSeasonMarks()` では**必ず新しい配列を作って入れ直している**。

### フォールバックの複製

画面上部の即時関数（IIFE）にある `window.__kotsusakuEnsureAllTimeCard` は、
本体の描画が失敗してカードが空のときだけ動く**保険**で、こちらはしおりに対応していない
（全期間の累計を出す）。通常は本体の `renderAllTimeCard()` が描くので表に出ない。

## 何度も使ったときの注意（設計上わかっていること）

- **科目別カードの「累計」もしおり以降になる**（2026-08-18に対応）。上の累計カードと数字がそろう。
  見出しは「累計」から「9/1〜」に変わるので、どの期間の数字かが分かる。
- **累計カードに出るのは「いまの旅」と「しおりまでの軌跡（＝それ以前の合計）」の2つだけ。**
  旅が3つ以上あっても、カードでは過去がひとまとめになる。
  期ごとの内訳は**設定の「これまでの旅」一覧**で見る、という役割分担にしてある。
- **目標総学習時間（`targetTotalH`）はアプリ全体で1つ。** 旅ごとに別の目標は持てない。
  しおりを挟むと予測は「いまの旅」で数え直されるので、目標も実質「いまの旅の目標」になる。
- **端末が2台あると、後から同期した方のしおりが残る**（`study-cust` は最後に書いた方が勝つ）。
- **古いバックアップを復元すると、しおりも当時の状態に戻る**（設定ごと入っているため）。記録は無事。
- **ストーリーの「2周目」（`storyLoopStartMin`）とは連動していない。** あちらは `allTimeTotal()` を
  基準にしており、しおりの影響を受けない。仕切り直しの仕組みが2つ並んで存在している状態。

## 動作確認の手順

```bash
cd /該当フォルダのパス
npm install --no-save jsdom
NODE_PATH=./node_modules node tools/verify-runtime.js   # 「アプリ由来エラーなし ✓」を確認
```

画面の確認は、`study-data` に7月・8月のデータを入れた状態で以下を見る（教訓#006・#007）：

1. しおりなし … 今まで通り「累計学習時間」。一覧も＋ボタンも出ない
2. しおりを過去の日付に … 見出しが「8/1〜の軌跡」に変わり、下に「🔖 しおりまでの軌跡（〜7/31） ○時間」
3. しおりを未来の日付に … 「9/1から新たな旅がはじまります」と出て、数字は0（マイナスにならない）
4. **2枚目を挟む** … 一覧が「第1の旅／第2の旅／第3の旅（いま）」と増える。カードは最新のしおり以降だけを数える
5. 前のしおりより前の日付を入れる … 弾かれて、入力欄が元に戻る
6. ✕を押すたび … しおりが1枚ずつ外れ、1つ前の旅の見え方に戻る
7. 記録より前の日付に挟む … 「🔖 しおりまでの軌跡 0分」の行は**出さない**
8. 昔の形（`seasonStart`）で保存された設定 … 起動時に一覧へ引き継がれる
9. **科目別カード（日・週・月）** … 見出しが「累計」→「9/1〜」に変わり、しおり前の分が抜ける。
   科目別の合計が、上の累計カードの数字と一致すること
10. **320×568（最小級の携帯）**でカードと「これまでの旅」の一覧が横にはみ出さないこと。
   「しおりまでの軌跡」の行はカードの**全幅**を使う1行にしてある（`.atc-prev{flex:0 0 100%}`）。
   細い列に押し込むと、狭い画面で1文字ずつ折り返して読めなくなる。
