# 数え直しの区切り日（章の区切り）

「9月から科目を変える」「同じ科目だけど気持ちを新たに数え直したい」ときに、
**8月までの記録は残したまま、9月からの学習時間を0から数え直す**ための機能。

---

## 何ができるか

設定 →「基本設定」→「はじめに」→ **数え直しの区切り日** に日付を1つ入れるだけ。

| 場所 | 区切りなし（初期状態） | 区切りあり（例：9/1） |
|---|---|---|
| 📚 累計学習時間カード | 「累計学習時間」＝全期間の合計 | 「9/1〜の記録」＝9/1以降の合計。下に「＋ 〜8/31の記録 ○時間」を1行で表示 |
| カードの1日平均・学習日数 | 全期間 | 9/1以降 |
| 開花予測（試験日までの予測） | 累計 ＋ 1日平均×残り日数 | **9/1以降の実績だけ**で予測（前の期の時間は混ざらない） |
| レベル・バッジ・スピリット・ストーリー | 全期間 | **全期間のまま（変えない）** |
| 週タブ・月タブ・ヒートマップ・科目別カード | 変化なし | 変化なし |

### レベルとバッジを区切らない理由

数え直しの対象にすると、9月1日にレベルが1に戻り、獲得済みバッジが消えたように見える。
積み上げてきたものが減る体験は避けたいので、**「数え直すのは時間の表示と予測だけ」**とした。

---

## 大事な前提：記録は1件も消えない

この機能が持っているのは**日付1つだけ**（`CUST.seasonStart`）。
学習記録の本体（`study-data`）には一切触らない。

- 区切り日を消せば（✕ボタン）、**すぐ元の「全期間の累計」表示に戻る**
- クラウド同期・バックアップ・「みんなの軌跡」の全体合計にも影響しない
- 設定の「すべてリセット」とはまったく別物（あちらは本当に記録が消える）

---

## 関係するコード（`index.html`）

| 名前 | 役割 |
|---|---|
| `CUST.seasonStart` | 区切り日（`'YYYY-MM-DD'`、空文字＝区切りなし）。`study-cust` に入るので**クラウド同期に自動で乗る**＝他の端末でも同じ区切りになる |
| `getSeasonStart()` | 区切り日を取り出す。`CUST` の初期化前に呼ばれても落ちないよう try/catch（教訓#004） |
| `seasonTotal()` / `seasonDays()` | 区切り日以降の合計（分）と学習日数。区切りなしなら `allTimeTotal()` / `allTimeDays()` と同じ |
| `beforeSeasonTotal()` | 区切り日より前の合計（分）＝「これまでの記録」 |
| `_fmtSeasonMD()` / `_fmtSeasonPrevLabel()` | `'2026-09-01'` → `'9/1'` / `'〜8/31の記録'` |
| `renderAllTimeCard()` | 累計カードの描画。区切りがあれば見出し・数字・日数を区切り後に切り替え、`.atc-prev` の行を足す |
| `renderForecast()` | 予測の集計に `seasonTotal()` / `seasonDays()` を使う |
| `_setSeasonStartValue()` / `_refreshSeasonNote()` | 設定画面の入力欄の処理と、下に出る「〜8/31の記録 ○時間 ／ 9/1〜 ○時間」の説明 |

### 集計キャッシュの注意

`_statMemo`（集計結果の使い回し）は**学習データが変わったときにしか消えない**。
区切り日を変えただけでは消えないので、`seasonTotal` / `seasonDays` は
**キーに区切り日を含めている**（`'seasonTotal|2026-09-01'`）。
新しく期間別の集計を足すときも同じようにすること。

### 保存のタイミング

区切り日は、他の設定（保存ボタンでまとめて確定）と違い、**入力したその場で保存**する
（`saveCust()` ＋ `persistTopSettingsNow()`）。試験日と同じ扱い。
設定画面を✕（キャンセル）で閉じても消えないよう、巻き戻し用の `_custSnapshot` にも書き込んでいる。

### フォールバックの複製

画面上部の即時関数（IIFE）にある `window.__kotsusakuEnsureAllTimeCard` は、
本体の描画が失敗してカードが空のときだけ動く**保険**で、こちらは区切りに対応していない
（全期間の累計を出す）。通常は本体の `renderAllTimeCard()` が描くので表に出ない。

## 動作確認の手順

```bash
cd /該当フォルダのパス
npm install --no-save jsdom
NODE_PATH=./node_modules node tools/verify-runtime.js   # 「アプリ由来エラーなし ✓」を確認
```

画面の確認は、`study-data` に7月・8月のデータを入れた状態で以下を見る（教訓#006・#007）：

1. 区切りなし … 今まで通り「累計学習時間」
2. 区切りを過去の日付に … 見出しが「8/1〜の記録」に変わり、下に「＋ 〜7/31の記録 ○時間」
3. 区切りを未来の日付に … 「9/1から数え始めます」と出て、数字は0（マイナスにならない）
4. ✕でクリア … すぐ「累計学習時間」に戻る
5. **320×568（最小級の携帯）**でカードが横にはみ出さないこと。
   「これまでの記録」の行はカードの**全幅**を使う1行にしてある（`.atc-prev{flex:0 0 100%}`）。
   細い列に押し込むと、狭い画面で1文字ずつ折り返して読めなくなる。
