# 有料化プラン：無料版と有料版の線引き・いま準備しておくこと

2026-07-06 作成／同日改訂。将来の有料コンテンツ提供を見据えた設計方針の記録。
実装時はこの文書を唯一の出どころとして参照する。

> **2026-07-06 ユーザー決定：有料は「応援課金」のみ。**
> 機能は一切有料化せず、応援してくれたユーザーにお礼（応援バッジ・きせかえテーマ等）を返すモデルに確定。

---

## 1. 基本方針：「勉強を人質に取らない」

コツサクの有料化は次の一線を守る。

> **習慣化と学習記録の核心機能は、永久に無料。**
> **有料にするのは「世界観を広げる楽しみ」だけ。**

理由：
- コツサクの強みは「責めない・積み上げ型」の哲学。核心機能を後から有料化すると、この信頼が一気に崩れる（既存ユーザーの離反・低評価レビューの最大原因）
- 市場の実証：Forestは「育成の楽しみ」への課金だけで世界6,000万人。楽しみへの課金は成立する
- 審査面：初回申請は無料のまま（決定済み）。課金は公開後のアップデートで追加

## 2. 無料版と有料版の線引き

### ずっと無料（コア機能）
| 機能 | 理由 |
|---|---|
| 学習記録・7科目管理・ストップウォッチ | アプリの存在意義そのもの |
| 統計・グラフ・レベル・バッジ | 積み上げの見える化＝習慣化の核心 |
| スピリット第1弾（現行8体）・ストーリー現行分 | 既存ユーザーが無料で得たものは絶対に取り上げない |
| 開花日カウントダウン・応援メッセージ現行分 | 同上 |
| データ同期・バックアップ | データを人質にしない（最重要） |
| リマインダー通知（Phase 1実装分） | 習慣化の核心機能のため無料 |
| みんなの軌跡 | コミュニティは全員参加が価値 |

### 有料＝「応援サポーター」のみ（採用決定）

| 項目 | 内容 |
|---|---|
| 形態 | **非消耗型の買い切り**（1回きりの購入。Apple/Googleの「購入の復元」で機種変更後も特典が戻る） |
| 中身 | 機能の解放ではなく「開発とコミュニティへの応援」＋お礼の特典 |
| お礼の特典 | ① 応援バッジ（バッジコレクションに表示される特別バッジ）<br>② きせかえテーマパック（桜以外の季節テーマ・配色）<br>③ 将来の追加候補：限定の色違いスピリットなど |
| 価格 | 基本は1段階（例：¥480）。実装時に「🌸つぼみ ¥320／🌸満開 ¥800」のような複数段階も検討（**全段階で特典は同じ**にし、バッジの見た目だけ変える＝金額で機能差をつけない） |

**消耗型（何度でも投げられる投げ銭）を採らない理由**：消耗型はストアの「購入の復元」の対象外のため、機種変更時に応援の記録を復元できず、お礼バッジが消える事故が起きる。買い切り型なら復元で確実に戻る。

### 将来検討（当面やらない・アイデアの記録）
| 候補 | 内容イメージ | 備考 |
|---|---|---|
| 追加ストーリーパック | スピリット新章（新タマゴ・新覚醒演出） | 応援課金が軌道に乗り、要望が強ければ検討 |
| 限定スピリット単売 | 季節限定・コラボ的な特別スピリット | 同上 |
| 応援メッセージパック | 開花日カウントダウンの追加メッセージ集 | 応援サポーターの特典に含める方が自然かも |

### 採らない方式
- **月額サブスク**：受験生は「合格したら終わり」の利用者。月額は心理的負担が大きく、解約忘れの不満も生む。買い切りが世界観にも合う
- **広告**：「広告なし」は市場リサーチで確認した明確な差別化ポイント。導入しない
- **機能制限型（無料は記録○日まで等）**：核心機能の人質化にあたるため禁止

## 3. いま（有料化の前から）準備しておくこと

### A. データ設計：購入記録の置き場所を予約する【最重要・Phase 1で実装】
- 同期データ・バックアップJSONに **`purchases`（購入済みパックのIDリスト）** の欄を今から確保しておく
- 後から欄を足すと、新旧バージョン間の同期・復元で不整合が起きやすい（データ形式は Web版・アプリ版で共通に保つ原則）
- 例：`purchases: ["story-pack-2", "theme-winter"]`（未購入なら空）

### B. コンテンツのモジュール化【Phase 1〜で意識】
- スピリット・ストーリー・テーマを「パックを後から追加できる」データ構造にしておく
- 新パック追加のたびに本体コードを書き換えるのではなく、定義リストに1件足せば済む形を目指す

### C. 機能フラグ（表示のON/OFFスイッチ）【Phase 1で導入】
- 「アプリ版か・Web版か」「購入済みか」で機能の表示を切り替える仕組み。通知機能のWeb版非表示分岐（決定済み）と同じ仕組みに乗せる

### D. ストア側の事前準備【Phase 2で。ただし時間がかかるので早めに着手】
- **Apple**：有料契約（Paid Applications Agreement）への同意・銀行口座・税務情報の登録。審査とは別に日数がかかるため、開発者登録と同時に済ませておく
- **Google**：決済プロファイルの設定。日本の開発者はGoogle Play上で販売者情報（特定商取引法に基づく表記＝事業者名・連絡先など）の掲載が求められる
- どちらも「課金を出す直前」ではなく「アカウント開設時」にやっておくと後で慌てない

### E. 規約類の増補【課金導入の直前でよいが、忘れない】
- プライバシーポリシーに課金関連の記載を追加（購入情報はApple/Googleが処理し、本アプリは購入済みフラグのみ保持、等）
- 簡単な利用規約（返金はストアの仕組みに従う旨、パック内容の変更可能性）

### F. 「何が愛されているか」の観測【今すでに動いている】
- 既存のanalytics（匿名利用データ）で機能の利用状況を見て、有料パックの題材選びに使う。新しい計測の追加は不要

## 4. 決めておくべき論点（実装時にユーザーへ確認）

1. **応援の端末間引き継ぎ**：Apple/Googleの「購入の復元」は同じストア内でしか効かない（iPhoneで応援した記録はAndroidに自動では移らない）。同期コードに応援フラグを乗せて両OSで特典を有効にするか、ストアごとの扱いとするかは実装時に決める
2. **価格の最終決定**：1段階（例：¥480）か複数段階か。ストア手数料（15%。小規模事業者プログラム適用時）を踏まえて設定
3. **応援バッジ・テーマの見た目**：デザインは実装時に相談して決める

## 5. 進め方（時系列）

1. **v1リリース（無料・課金なし）** ← 現ロードマップ通り
2. リリース後、購入基盤（A〜C）の実装＋ストア側設定（D）
3. **「応援サポーター」を正式リリース**（お礼バッジ＋きせかえテーマ付き）
4. 反響を見て特典を追加（限定色違いスピリット等）。大型パック等は要望が強ければ「将来検討」から再検討
